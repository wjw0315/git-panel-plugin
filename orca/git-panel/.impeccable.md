# Design Context — Orca Git Panel

> Scope: **this directory (`orca/git-panel/`) only.** The Paseo plugin at the repo root (`client/`, RN + `PluginTheme`) is a separate surface with its own constraints and is **not** governed by this file — do not copy these rules up to the repo root, and do not apply them to `client/`.
> Source: `impeccable init`, 2026-11-20. Answers from the project owner; everything else read from the code.

## Design Context

### Users

A single developer — this machine's Orca user — working in the **right sidebar panel** (narrow: roughly 280–360 px), during the few minutes right after an agent finishes: review what changed, stage, commit, push or sync, stash and restore, switch between the main repo / submodule / nested repo in one workspace.

- Context: mid-task, hands on keyboard, often several agents in flight.
- Job to be done: land or undo the working tree without dropping to a terminal, without leaving Orca, without breaking the repo.
- Emotional target: **confidence**. Nothing surprising, nothing irreversible without a second press.

### Brand Personality

Three words: **宿主延伸 · 高密度 · 可预期** (host-native · dense · no surprises).

The panel should read as something Orca shipped, not a plugin wearing a costume. It earns identity from *density and ordering*, not from color, icon, or flourish.

### Aesthetic Direction

- **Host is the design system.** Color, spacing scale, radii, typography, and elevation come from Orca's `components` host (`Stack` / `Row` / `Card` / `List` / `ListItem` / `Button` / `IconButton` / `Badge` / `Text`). Never invent a palette, never hardcode hex, never add CSS-like styling.
- **Semantic props only.** No `className` / `style` / lowercase DOM tags. Icons are restricted to the fixed `IconName` whitelist — the panel and status bar both use `layers` (deliberately not `branch`, which collides with Orca's built-in Source Control).
- Dark and light both, following the host. No self-managed theme, no `prefers-color-scheme` branching.
- **Replication mandate (2026-11-20, supersedes the earlier anti-reference).** The owner's instruction is *1:1 replica of Orca's built-in Source Control*, plus one addition: the repo switcher. So the former "if it could be mistaken for the built-in, the ordering is wrong" rule is retired — being indistinguishable from the built-in on a single-repo workspace is now the **target**. Keep the delta list short and explicit (`docs/UI-DESIGN.md` §7); every deviation must have a host-capability reason, never a taste reason.
- Still an anti-reference: inventing a second visual language on top of the host — custom colors, icon stacks, hover-only affordances. Replication means copying the built-in's *order and vocabulary*, not decorating around it.
- Motion: none beyond host-supplied state transitions. No decorative animation, no skeleton shimmer.

### Constraints (verified, not stylistic)

| Constraint | Consequence |
|---|---|
| Components panel renders in the right sidebar only; no plugin runtime on Orca mobile | Single-column layout, no responsive breakpoints to design for |
| `orca plugin check` refuses `IconButton` inside a `ListItem` with `onPress` | Clickable row = selection only; row-level actions live in rows that are not clickable |
| 2000 ms transpile budget, charged to the entry file first | `src/panel.tsx` stays a 7-line re-export; real UI in `app.tsx` / `views.tsx` / `rows.tsx` / `tabs-*.tsx` |
| Icon set is a closed whitelist (~50 names) | No self-drawn glyphs; status is carried by text, `Badge`, and `tone` |
| Gates before any visual claim | `tsc -p .` (global `tsc` 5.9; `npx tsc` fails — this package installs no deps), `orca plugin test .`, `orca plugin check .` (renders 4 scenario PNGs for eye review) |

### Design Principles

1. **Host token or nothing.** Every visual value traces to an Orca component prop. A diff that adds a color, radius, or shadow is wrong by default.
2. **One primary action chain per screen.** Commit card pinned at top (message → amend → 提交 / 提交并推送 / 提交并同步), everything else degrades into groups that can collapse. Reviewing and committing is the reason the panel opens.
3. **State is text and badges, not ornament.** `已暂存 3 · 已修改 2 · 未跟踪 1` beats three colored dots. Dirty dot only where a list must stay one line (repo switcher).
4. **Destructive actions are visually separated and confirmed.** `tone="danger"` for discard/delete/force-push; the confirm question renders inline as a row, never a modal that steals the whole sidebar.
5. **Narrow width first.** Single column, no horizontal scroll, path text truncates from the left (basename visible), and long file paths never push row actions off-screen.

### Verification

```sh
cd orca/git-panel
tsc -p .                     # types, global tsc (run `orca plugin types .` once in a fresh checkout)
orca plugin test . --json    # panel + worker tests
orca plugin check . --json   # 4 scenarios rendered to PNG — the actual visual evidence
```
