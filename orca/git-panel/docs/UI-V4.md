# Orca Git 面板 · UI 交互稿 v4.2

Status: **与实现对版**（2026-11-21）。`orca/git-panel/src` 已按本文实现；可点原型 [`ui-v4.html`](ui-v4.html)（六个场景按钮，点得动）。
上一版 v3（1:1 复刻内置、五页签）保留在 [`UI-DESIGN.md`](UI-DESIGN.md) 作对照。

视觉语言走「内置 Source Control 影子」派：树、状态字母、提交区词汇沿用内置；交互走**单页 + 顶部页签**，没有返回键。

## 1. 布局

```
┌ GIT ─────────────────────────────────────────┐
│ [主仓库 · git-panel-plugin  main ●   ▾]       │ 仓库切换器（多仓库时才出现）
│ ⎇ main ⟳            ● 有改动   ⌕   ···        │ 分支行 + 脏标记 + 搜索 + 更多
│ ↑1 ↓0 · origin/main        ↓ 基准领先 2  PR   │ 上游 / 基准 chip / PR
├───────────────────────────────────────────────┤
│ 合并进行中 · 2 个文件未解决   [中止][完成合并]  │ 冲突条（仅冲突时，压在页签上方）
├───────────────────────────────────────────────┤
│ 提交  更改 3  基准  历史 2  贮藏 1  分支 4  更多 │ 宿主 Tabs，标签带计数
├───────────────────────────────────────────────┤
│ （当前页内容，纵向滚动）                        │
└───────────────────────────────────────────────┘
```

实机宽度约 398px（`orca plugin shot` 实测），单列、永不横向滚动。

## 2. 七个页签

| 页签 | 内容 | 卡头/工具行 |
|---|---|---|
| 提交 | 信息框、amend、**已暂存的文件列表**、`提交` + `▾`（提交并推送 / 同步 / 强推） | 左：`已暂存 N`；右：全部丢弃 |
| 更改 | 文件树（树形 / 平铺）、逐文件动作、目录级动作 | 左：`N 个文件`；右：展示方式下拉 + 全部暂存 + 全部丢弃 |
| 基准 | 基准选择下拉、`ref`、领先数与提交清单、两个拉取按钮 | 失败/降级/覆盖/回退提示就地显示 |
| 历史 | 过滤框、提交列表、加载更多 | 需要时才拉取（`selectTab('history')`） |
| 贮藏 | 新建（含未跟踪）、应用 / 弹出 / 删除 | — |
| 分支 | 每行两行文字（名字 / 远端·当前标签）+ `切换` + 删除图标 | 右上 `＋ 新建分支` |
| 更多 | 内置溢出菜单的 13 项，带不可用原因 | — |

## 3. 核心交互

**文件在「提交」与「更改」之间移动。** 一个文件要么在提交页（已暂存），要么在更改页。点更改页的 `+`，它当场消失并在提交页出现；反向点 `−` 回来。提交页列出来的就是这次要提交的内容，不需要二次确认。

**提交是两段式。** 主按钮 `提交`，右侧 `▾` 在页内展开另外三种收尾；每种右侧写明不可用原因（`需要提交信息` / `未发布` / `有冲突`）。

**更改页两种展示方式**（选择按插件记忆）：

| 模式 | 行结构 | 目录 |
|---|---|---|
| 树形 | 只显示文件名 | 单行目录：`▸ 名字 N`，右侧目录级 `+ / 🗑`，子项缩进 14px，展开状态按插件记忆 |
| 平铺 | 文件名 + 目录副行 | 不分组 |

**基准页四个状态**（都就地显示，不弹窗）：

| 状态 | 呈现 |
|---|---|
| 正常 | `基准领先 N 个提交` / `基准已合入` + 前 5 条提交 + 两个按钮 |
| fetch 无权限/网络失败但本地有 ref | **降级合并**，灰字「没能获取最新（无访问权限），已用本地缓存完成合并」 |
| 失败（本地也没有 ref，或 merge 失败） | 红字一行中文原因 + `查看原始输出`（展开 git stderr）+ 收起 |
| 会覆盖未跟踪文件 | 橙字「合入会覆盖 N 个未跟踪文件」+ 列出前 10 个路径，两个按钮禁用（此时完全不动 HEAD） |
| 选中的 ref 已不存在 | 自动回退远端默认，灰字「原来选的基准已不存在，已回退到 origin/main」，并清掉该仓库记住的选择 |

两个拉取动作：`获取并合并`（`fetch --prune` + `merge --no-edit <ref>`）与 `仅合并本地基准`（跳过 fetch）。都不推送。

**分支页每个分支一行**：名字一行、`远端 / 当前` 标签一行；右侧最多一个 `切换` 加一个删除图标（删除二次确认时才变 `强制删除` 文字按钮）。这样长分支名不会把按钮顶出右边界。

## 4. 文案

| 位置 | zh | en |
|---|---|---|
| 页签 | 提交 / 更改 / 基准 / 历史 / 贮藏 / 分支 / 更多 | Commit / Changes / Base / History / Stashes / Branches / More |
| 提交禁用 | 未暂存任何文件 / 需要提交信息 / 有冲突 | Nothing staged / Needs message / Conflicts |
| 基准状态 | 基准领先 N 个提交 / 基准已合入 / 本地还没有这个基准分支 | N commits ahead / Up to date / Not fetched |
| 基准动作 | 获取并合并 / 仅合并本地基准 | Fetch and merge / Merge local base only |
| 基准失败 | 获取失败：没有访问权限或仓库不存在。可以先点「仅合并本地基准」。 | Fetch failed: no access to the remote… |
| 覆盖拦截 | 合入会覆盖 N 个未跟踪文件，先移走或删除它们 | Merging would overwrite N untracked file(s)… |
| 分支动作 | 切换 / 删除 / 强制删除 | Switch / Delete / Force delete |

## 5. 与 v3 的差异

| 项 | v3 | v4.2 |
|---|---|---|
| 导航 | 5 个平级页 + 返回条 | 顶部 7 个页签，无返回键 |
| 已暂存位置 | 页面下半部的「已暂存的更改」组 | 提交页内部 |
| 基准分支 | 「更多」页里的卡 | 独立页签，可选任意 ref、可降级、可预检覆盖 |
| 溢出动作 | 独立页 | 第 7 个页签（「更多」） |
| 文件列表 | 只按一级目录分组 | 树形（多层）/ 平铺 双视图 |
| 失败呈现 | 一行 `操作失败` + 原始英文 | 分类中文原因 + 原始输出按需展开 |

## 6. 已知约束

- **面板宽度拿不到**：Orca 不向插件暴露面板宽度，也没有容器宽度钩子，所以「宽档右栏预览」只在原型里，实机只有单列 + 行内展开。
- **冲突行只读**：内置的「保留我方/对方/标记已解决」需要 `checkout --ours/--theirs` + `git add`，尚未进 worker；现在只有中止/继续/完成合并（工单之外）。
- **AI 生成提交信息 / PR 编辑器 / 图谱画布**：跳内置，面板底部一行入口。

## 7. 实机验收

```sh
cd orca/git-panel
tsc -p .                                   # 0 错误
orca plugin test . --json                   # 48 测试
orca plugin check . --json                  # 8 场景 issues 全空
orca plugin shot local.git-panel --panel git-panel --out /tmp/panel.png --json
```

`orca plugin shot` 是唯一能看真实渲染的手段。注意两点：
- 源码一改，`consentFingerprint` 就变，插件会变 `pending`，面板直接不加载——先重新批准再截图。
- 往插件目录里写任何文件（包括临时文件）同样会改指纹；造脏数据请在插件目录外。

## 8. 原型

[`ui-v4.html`](ui-v4.html)：六个场景（有改动 / 干净 / 树形文件 / 基准无权限 / 基准降级 / 基准未跟踪冲突 / 合并冲突）+ 暗色切换。
可点的交互：页签切换、暂存与取消暂存（文件在提交与更改之间移动）、树形/平铺切换、目录展开、提交菜单、基准拉取四种结局、原始输出展开、分支删除二次确认。
