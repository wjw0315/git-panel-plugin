# 文件树上下文菜单：文件夹/文件就地操作

Status: ready-for-agent

原型：分支 `prototype/file-tree-context-menu`（56a1c3c），**用户已拍板变体 B（锚定浮层）**（2026-11-17）。评审稿 `prototype.html` 在该分支；本文件是定案的唯一事实源。

## 问题陈述

文件树目前只能「点开预览」。想重命名一个文件、建一个空目录、删掉一个临时文件、把路径复制给同事、或把截图放进工作区，都必须离开面板去终端或 Finder——面板里看得见文件却摸不着，日常管理的最小闭环缺失。

## 方案

对树行**右键**（桌面）或**长按**（移动端）弹出**锚定浮层菜单**（原型变体 B）：贴着触发坐标出现的紧凑菜单（宽约 220px，图标 + 文字项，组间分隔线），有坐标时锚定坐标、无坐标（长按）退化为树面板内底部居中。菜单项按目标类型固定：

- **文件夹**（7 项）：重命名 · 复制路径 · 在 Finder 中显示 ‖ 新建文件 · 新建文件夹 · 上传文件 ‖ 删除
- **文件**（6 项）：重命名 · 复制路径 · 保存 ‖ 在 Finder 中显示 · 用默认应用打开 ‖ 删除

分组（1 主操作 / 2 次级操作 / 3 危险区），删除红色置底。所有写操作经确认/输入对话框后执行，成功后树局部刷新；失败 toast 展示原因。

## 实现决策

**契约（shared schema）**

- 新增单一 RPC `git.fs-op`，仿 `actionRpc` 先例：输入为 zod union（`kind: "createFile" | "createDir" | "rename" | "delete" | "upload" | "reveal" | "open"`），输出统一 `{ ok: true } | { ok: false, error: { code, message } }`。不按操作各开一条 RPC。
- `rename` 仅支持同目录改名（`path` + `newName`）；`createFile/createDir` 目标为 `parentPath + name`；`upload` 额外带 base64 `content`；`reveal/open` 只带 `path`。
- 错误码沿用/新增：`invalid-path`、`write-denied`、`already-exists`、`not-found`、`too-large`、`nested-repo`、`edit-disabled`、`opener-unavailable`。

**服务端（新模块，仿 files.ts/actions.ts 组织）**

- 路径安全全部复用 `assertSafeRelative` / `realInside`：拒绝绝对路径、`..`、`.git`、符号链接逃逸。
- `createFile/createDir/rename/upload` 受现有 `allowFileEdit` 设置总闸；`reveal/open` 受**新设置** `allowSystemOpen`（默认开）。
- `delete`：文件夹递归删除，删除前做嵌套仓库探测（沿用 actions.ts 对 `.git` 存在性检查的思路，命中即 `nested-repo` 拒绝）。
- `upload`：base64 解码后上限 16 MiB（独立于文本编辑的 2 MiB 上限），任意扩展名（`.git` 内除外），目标已存在拒绝；直接写入（无需 baseSha 冲突检测，语义为「新建」）。
- `reveal/open`：服务端以 argv 数组 spawn 系统打开器（macOS `open -R` / `open`；Linux `xdg-open`；Windows `explorer`），不走 shell；平台无可用打开器或 spawn 失败返回 `opener-unavailable`（远程 daemon 场景由此自然报错）。

**客户端**

- 触发：行 `Pressable` 挂 `onContextMenu`（桌面，RN-web DOM 透传；**实现时首验宿主是否透传**，不透传则桌面退化为长按并记录到 spec 备注）与 `onLongPress`（移动端）。RN 类型无 `onContextMenu`，参照原型分支的强转写法。
- 菜单形态（定案 B）：树面板内绝对定位浮层（非宿主 Modal），宽 220px，紧凑行（图标 13 + 12px 文案），三组分隔线，删除红色；有坐标锚定坐标（视口内回卷），无坐标（长按）面板内底部居中。半透明遮罩点击关闭，Esc 关闭。
- 菜单项模型与分組复用原型分支 `menuActions` 的结构（folder 7 项 / file 6 项）。
- 复制路径：拆成两项（2026-11-17 增量）——「复制相对路径」（仓库相对）与「复制绝对路径」（daemon 仓库根 + 相对路径；根由 `dir-list` 输出新增的 `root` 字段下发，未取到时该项禁用）。客户端 `copyText`，不落服务端写操作。
- 保存：仅 `path === 当前打开文件 && 草稿脏` 时可点（disabled 而非隐藏），走现有 autosave flush。
- 删除/重命名目标为当前打开文件时：先 `flushBeforeLeaving`（冲突则停在冲突横幅），成功后关闭预览再执行；重命名成功后预览指向新路径。
- 对话框：宿主 `Modal` + `TextInput`（changes.tsx 提交对话框先例）：重命名预填并全选、新建输入名称、删除确认框写明路径；前端先做名称校验（无 `/`、`..`、不为 `.git`），服务端再拦。
- 树刷新：mutation 成功后按受影响目录重建 `children` 对应项（父目录列表重取），不折叠已有展开状态。
- 上传入口仅桌面：宿主 DOM file input 能力探测，移动端隐藏该项。
- i18n：strings.ts en/zh 全量新增（菜单项、对话框、错误、确认文案）。

## 测试决策

- 好测试只断言外部行为（菜单出现什么、点了什么 RPC、树变成什么），不断言内部实现细节。
- **接缝 1（现有最高）**：`FilesTab` 组件测试 + RPC 桩（`tests/stubs/plugin-client`），覆盖：分类型菜单项集与分组、右键/长按触发、复制路径调用剪贴板、保存禁用态、对话框流转与入参、mutation 成功后刷新、失败 toast、Esc/点击外关闭。先例：`tests/files-tab.test.tsx`、`tests/files-responsive.test.tsx`。
- **接缝 2（唯一新增，服务端）**：fs-op 服务端模块对真实临时目录直测：路径逃逸/`.git`/目标已存在/嵌套仓库/体积上限/rename 跨目录拒绝；`reveal/open` 只断言按平台构造的 argv 与拒绝条件（spawn 打桩，不真开 Finder）。本仓首批服务端测试，测试文件沿用 `.test.tsx` 命名以套用现有 vitest include。
- 原型分支 `prototype/file-tree-context-menu` 是交互形态的 primary source：菜单结构、分组、锚定与退化行为以其为准，不重新发明。

## 范围外

- 移动端上传（宿主无 file picker API）
- 跨目录移动/拖拽（本期 rename 仅同目录）
- 回收站/软删除（`rm` 直接删：已跟踪文件可由 git 恢复，未跟踪文件不可恢复——确认框文案明示）
- 文件夹大小统计、菜单项自定义/排序设置
- 远程 workspace 的路径换算（复制路径永远给仓库相对路径，不猜本地绝对路径）
