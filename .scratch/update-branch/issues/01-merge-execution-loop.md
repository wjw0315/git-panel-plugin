# 01: 合并执行闭环——从面板发起合并并成功落库

**What to build:** 用户在分支面板工具区看到「更新分支」入口，点开后是变体 A 卡片式对话框（本期只有「合并」一张卡）。选定本地或远端来源分支后，预检块立即显示「来源 → 当前分支」方向与将带入的提交数（对齐操作者合并报备铁律），确认后仓库产生一个合并提交（保留历史语义），快照自动刷新，全程不自动 push。交互规格与形态以 `.scratch/update-branch/spec.md` 及拍板的原型变体 A 为准。

**Blocked by:** None（可立即开始）

**Status:** resolved

- [ ] 分支面板工具区出现「更新分支」入口按钮，带悬停 hint（hint 覆盖测试把关）
- [ ] 对话框呈现合并卡片（默认选中）、来源分支下拉（本地/远端分组）；远端分支以完整 ref 传递，不被截断
- [ ] 选定分支后预检块显示方向文案与将带入的提交数

- [ ] 来源分支等于当前分支时：前端确认禁用，服务端拒绝
- [ ] 脏工作区执行被拒绝并给出可读错误（复用现有错误码分类）
