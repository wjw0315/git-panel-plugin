# 03: 两处入口接入与冲突行动作纠正

**What to build:** 把解决清单接到用户真正会停下的两个地方——变更视图底部的「冲突 N」行，以及「更新分支」对话框的进行中态；同时纠正冲突行上那个对 unmerged 路径必报错的「丢弃」按钮。批量选择冲突文件时要能一次标记解决。

**Blocked by:** 01、02

**Status:** ready-for-agent

- [ ] 变更视图底部的「冲突：N」行改为可点击入口，点开弹出解决清单
- [ ] 该入口仅在存在冲突文件时出现；无冲突时不渲染任何空壳
- [ ] 「更新分支」进行中态内嵌同一份解决清单，原「在终端或外部工具解决冲突」的说明文案相应改写（只在中止场景保留指引）
- [ ] 继续成功后对话框自动关闭并 toast，快照刷新使进行中态消失
- [ ] 中止路径保持可用并回到操作前状态
- [ ] `status === "conflicted"` 的变更行不再渲染「丢弃」按钮，次要动作改为「标记已解决」
- [ ] 冲突文件可加入现有选择集合，选中后批量「标记已解决」一次执行
- [ ] 双语文案补齐（含改写后的进行中说明）
- [ ] 集成渲染测试（`rpc.handler` 桩）：冲突快照渲染出入口 → 打开清单 → 点击动作发出 `git.action`（`kind: "resolve"`）
- [ ] 回归测试：冲突行不再出现「丢弃」
- [ ] typecheck 与现有测试回归通过
